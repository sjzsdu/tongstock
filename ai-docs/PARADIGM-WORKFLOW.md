# 目标研究工作流与成功指标

本文档定义 TongStock 范式研究系统的用户工作流、信息架构、关键路径和事件指标。核心设计原则：**用户不需要理解 Model、Session 或内部 Agent**。

## 1. 目标用户

| 角色 | 目标 | 核心操作 |
|------|------|----------|
| **研究者** | 发现和验证交易范式 | 提出假设 → 运行实验 → 审查结果 |
| **评审者** | 把关范式质量 | 审查证据 → 批准/拒绝晋级 |
| **监控者** | 跟踪范式表现 | 查看前向运行 → 发现漂移 → 降级 |

---

## 2. 信息架构

### 2.1 页面结构（用户视角）

```
/paradigms              → 范式列表（按状态分组）
/paradigms/new          → 新建假设
/paradigms/:id          → 范式详情（当前状态 + 版本历史）
/paradigms/:id/evidence → 证据报告（指标 + 准入判定）
/paradigms/:id/lifecycle → 生命周期（状态转换历史）
/paradigms/:id/forward  → 前向运行（实时信号 + P&L）
/research               → 研究工作台（假设 → 实验 → 候选）
/audit                  → 审计日志（追溯链）
```

### 2.2 关键概念映射

| 用户概念 | 内部对象 | 说明 |
|----------|----------|------|
| "交易想法" | Hypothesis | 用户提出的研究假设 |
| "回测" | Experiment | 在历史数据上运行规则 |
| "候选策略" | Candidate | 通过初步筛选的范式 |
| "验证报告" | ValidationReport | 准入标准评估结果 |
| "模拟盘" | ForwardRun | 前向观察运行 |
| "策略档案" | ParadigmVersion | 范式的版本快照 |

## 3. 核心工作流

### 3.1 研究闭环

```
 ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
 │ 1.提出   │───▶│ 2.运行   │───▶│ 3.审查   │───▶│ 4.验证   │───▶│ 5.观察   │
 │ 假设     │    │ 实验     │    │ 反证     │    │ 准入     │    │ 前向     │
 └──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
                       │               │               │               │
                       ▼               ▼               ▼               ▼
                  候选范式         淘汰/保留       准入报告        晋级/淘汰
```

#### 步骤 1: 提出假设

**用户操作**: 在 `/paradigms/new` 页面描述交易想法
- 选择股票池（全市场/板块/个股）
- 选择持有周期（日内/短线/中线/长线）
- 描述买入条件（自然语言或结构化）
- 描述卖出条件

**系统行为**:
- 创建 Hypothesis 记录
- 状态: `hypothesis`
- 不需要用户理解 Agent 或 Model

#### 步骤 2: 运行实验

**用户操作**: 点击"运行回测"
- 系统自动选择数据快照和特征集
- 系统自动生成规则集并执行
- 展示回测结果（收益、胜率、回撤、样本量）

**系统行为**:
- 创建 DatasetSnapshot + FeatureSet + Experiment
- 状态: `experiment` → `candidate`
- 产出 Candidate 和初始指标

#### 步骤 3: 审查反证

**用户操作**: 在 `/paradigms/:id` 页面审查结果
- 查看成本后收益（非毛收益）
- 查看样本量是否充足
- 查看跨窗口和跨市场状态表现
- 查看 Red Flags（未来数据、幸存者偏差等）

**系统行为**:
- 展示 Evidence 和 AdmissionResult
- 标记 MustFix 项
- 允许用户修改假设后重跑

#### 步骤 4: 验证准入

**用户操作**: 点击"提交验证"
- 系统执行完整的准入评估
- 生成 ValidationReport
- 评审者审查并批准/拒绝

**系统行为**:
- 状态: `validation`
- 调用 `evidence.CheckAdmission()`
- 产出 ValidationReport 和准入等级

#### 步骤 5: 前向观察

**用户操作**: 在 `/paradigms/:id/forward` 页面启动模拟盘
- 系统开始前向运行
- 实时展示信号和 P&L
- 监控漂移指标

**系统行为**:
- 状态: `observation`
- 创建 ForwardRun
- 定期检查漂移
- 晋级或淘汰

### 3.2 晋级与淘汰

```
observation ──(漂移可控 + 前向达标)──▶ promoted (有限实盘)
            ──(漂移超标)──────────────▶ relegated (退回观察)
            ──(持续表现差)────────────▶ retired (淘汰)
```

## 4. 首个端到端用例

### 用例: MACD 金叉趋势跟踪范式

1. **假设**: "沪深300成分股中，MACD金叉且MA20向上时买入，死叉卖出，持有1-5天"
2. **实验**: 在 2020-2024 数据上运行，产出 120 个交易周期
3. **审查**: 成本后收益 +8.5%，95%CI [2.1, 14.9]，最大回撤 7.2%，跨3个窗口均正收益
4. **验证**: 准入评分 82 分（Gold 级别），无阻塞项
5. **观察**: 前向运行 3 个月，收益 +3.2%，漂移在可控范围
6. **晋级**: 状态转为 `promoted`，可用于有限实盘

## 5. 成功指标

### 5.1 研究闭环指标

| 指标 | 定义 | 目标 |
|------|------|------|
| **假设转化率** | 假设 → 候选的比例 | > 20% |
| **候选通过率** | 候选 → 验证通过的比例 | > 10% |
| **验证晋级率** | 验证 → 观察的比例 | > 50% |
| **观察存活率** | 观察 → 晋级的比例 | > 20% |
| **范式存活期** | 晋级到淘汰的平均时间 | > 6 个月 |
| **漂移检测延迟** | 漂移发生到检测的时间 | < 5 个交易日 |

### 5.2 证据质量指标

| 指标 | 定义 | 目标 |
|------|------|------|
| **证据完整率** | 有完整追溯链的范式比例 | 100% |
| **复现成功率** | 同版本重跑结果一致率 | 100% |
| **Red Flag 检出率** | 审计发现问题的范式比例 | 追踪趋势 |
| **准入评分分布** | Gold+ 比例 | 追踪趋势 |

### 5.3 用户效率指标

| 指标 | 定义 | 目标 |
|------|------|------|
| **假设到实验时间** | 从提出到回测完成 | < 5 分钟 |
| **实验到验证时间** | 从回测到准入报告 | < 10 分钟 |
| **验证到观察时间** | 从准入到前向启动 | < 1 天 |
| **用户操作步骤数** | 完成一个闭环的最少步骤 | < 10 步 |

---

## 6. 非目标

- 不以页面数量或 Agent 数量为成功指标
- 不要求用户理解 Model、Session 或内部 Agent 架构
- 不以保证存在永久盈利范式为目标
- 不以实盘资金量为阶段 0 的验收条件
