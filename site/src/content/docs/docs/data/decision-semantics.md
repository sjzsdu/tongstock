title: 决策口径
description: 证据等级、fail-closed、inferred 血缘、T+1 与停牌——这套系统在不确定时怎么处理。
---

这一页说明 TongStock 在“数据不够、证据不足、无法执行”时到底怎么做。它是这套系统可信度的来源，也是它经常给出“空结果”的原因。

## 1. 证据来自验证制品，不是打分

方法被编译成带哈希的结构后，要在**冻结的真实数据**上跑验证：回测、统计检验、以及一个批评者（critic）角色提出反证。产物是 `EvidenceBundle`，用结果哈希索引。

UI 上看到的“证据等级”就是这份 bundle 的状态，不是一个人为设定的分数。查一个方法有多少证据：

```bash
./tongstock validate list                    # 按方法哈希列出可引用的验证制品
./tongstock validate evidence <result-hash>  # 按结果哈希查详情
```

## 2. 没有足够数据就失败，而不是补一个看起来合理的值

三种典型的 fail-closed：

| 情况 | 处理 |
| --- | --- |
| 历史验证缺少某时点的市值序列 | 明确失败，**不拿今天的市值回填过去** |
| `cache_only` 模式下数据缺失 | 报错并提示如何同步或切换一致性模式 |
| 当日没有方法通过门槛 | 返回空榜单，并给出被排除原因分布 |

“用今天的市值算历史”是量化分析里最常见的自欺方式；把这条写死在代码里，是为了让结论可复核。

## 3. 血缘缺失就标 `inferred`

持仓卖出判断需要知道“这只票当初是按哪个方法买的”。如果历史持仓没有原始方法记录，决策里会把血缘标为 `inferred`（推断），而不是假装它来自某个方法。

这意味着：`inferred` 的持仓，其退出条件是基于当前可得信息推断的，可信度低于有完整血缘的持仓。

## 4. 不能执行就说不能执行

- **停牌**：不会报告“已卖出”，而是把不可执行的状态单独列出。
- **T+1**：当日买入的仓位不会被算作可卖。
- **执行约束**：前向运行里有 `execute` / `finalize` 两个状态推进步骤，未满足约束时不会被静默跳过。

## 5. 验证口径属于方法本身

观察窗口、目标幅度、价格基准、成功条件都是**方法的一部分**，不是全局默认：

- 系统不再把“20 个交易日”“收盘价达到”当成所有方法的默认口径；
- 兼容旧模板时会明确标记为确定性 fallback；
- 方法股票池也是结构化范围（市值上下限、板块、是否排除 ST 等）。

所以比较两个方法时，要比的是“方法 + 它的口径”，而不是两个裸规则。

## 6. 分层重验，防止结论只在大盘股上成立

```bash
./tongstock method stratify
```

按历史日均成交额把股票池分层，逐层重验样本外表现。任何一层崩掉都会暴露——这是对“结论只在流动性最好的那几只股票上成立”的常规防御。

## 7. 前向监控，防止方法悄悄衰减

上线不是终点。前向运行记录真实表现，监控对漂移、衰减、集中度打分并产出告警；告警必须显式 `ack` 与 `resolve`，不会“刷新一下自动消失”。

相关端点：`/api/forward/*`、`/api/monitoring/*`，见[范式、监控与前向跟踪](/docs/api/paradigm-monitoring-forward/)。

## 一句话总结

> 有证据才推荐，没证据就说没有；不能执行就说不能执行；推断出来的东西标成推断。

如果你觉得系统“太保守”，那通常是它在正确工作。放宽门槛的代价，会在回撤里体现。
